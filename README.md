# 🎓 Student Performance Prediction System

A beginner-friendly machine learning project that predicts a student's **final grade (G3, 0–20)** using academic and background data from the [UCI Student Performance Dataset](https://archive.ics.uci.edu/dataset/320/student+performance).

Built as a **Teacher's Dashboard**: a teacher enters each student's details, gets the predicted grade plus a **performance category**, and the app generates **personalized improvement suggestions** for every student (study habits, attendance, grade trend, distractions, support needed). All records are stored in a **SQLite database** and can be downloaded as a **class report (CSV)**.

Built with Python, scikit-learn and Streamlit.

## 🚀 How to Run

```bash
# 1. Create and activate a virtual environment
python -m venv venv
venv\Scripts\activate        # Windows
source venv/bin/activate     # Mac/Linux

# 2. Install dependencies
pip install -r requirements.txt

# 3. Train the model (creates model.pkl and model_meta.pkl)
python train_model.py

# 4. Launch the web app
streamlit run app.py
```

The app opens in your browser. Enter student details → click **Predict Performance** → see the predicted grade, its category, and the record saved in the database (viewable in the *Prediction History* section).

## 🧠 Key ML Concepts (interview-ready)

- **Features (X)** – inputs: study time, absences, parents' education, G1, G2, etc.
- **Target (y)** – what we predict: final grade `G3` (0–20).
- **Regression vs Classification** – G3 is a continuous number → **regression**. Predicting Pass/Fail would be classification.
- **Train/Test split** – the model trains on 80% of students and is evaluated on 20% it has never seen, simulating real new students.
- **Overfitting** – model memorizes training data but fails on new data (very low train error, high test error).
- **Underfitting** – model is too simple to capture the pattern (high error on both sets).
- **Data leakage** – using information at prediction time that would not realistically be available. ⚠️ *See note below.*
- **Evaluation metrics**:
  - **MAE** – average absolute error in grade points (easy to interpret).
  - **RMSE** – like MAE but punishes large errors more heavily.
  - **R²** – fraction of grade variation the model explains (1.0 = perfect).

### ⚠️ Important: the G1/G2 data-leakage discussion

G1 (1st period grade) and G2 (2nd period grade) are the strongest predictors of G3. Using them is **only valid if the prediction is made during the school year**, after those grades exist. If the goal is to predict performance **at the start of the year** (early-warning system for at-risk students), G1/G2 are not yet known and using them would be **data leakage** — the model would look accurate in testing but fail in the real world. For that scenario, retrain without G1/G2 (expect lower R² — that drop is honest, not a bug).

## 🗃️ Database

Predictions are stored in a **SQLite** database (`predictions.db`, auto-created) in a table called `predictions` with columns for the student's name, every input, the predicted grade, its category, the improvement suggestions, and a timestamp. SQLite is a file-based database — no server setup needed — making it ideal for a beginner project while still demonstrating real database skills. Old databases from version 1 are **migrated automatically** when the new app starts.

## 💬 Personalized Improvement Suggestions

After each prediction, the app generates targeted advice for the student using simple, explainable rules on the same inputs the model used:

- **Grade trend** — G2 dropping vs G1 → "revise weak topics before the final exam"
- **Study habits** — very low weekly study time → "build a fixed daily schedule"
- **Attendance** — high absences → "regular attendance matters"
- **Past failures** → "focus on fundamentals, ask for help early"
- **Distractions** — internet + low study time → "focused sessions with notifications off"
- **Background support** — low parental education → "use free online resources"

This rule-based approach is deliberate: every suggestion maps to a real input feature, so it is fully explainable — unlike a black-box deep learning model. The teacher can also **download the whole class report as CSV**.

### Possible technical questions & short answers
- **Why Random Forest over Linear Regression?** Lower test RMSE — it captures non-linear interactions (e.g., failures × study time) that a straight-line model cannot.
- **Why a pipeline instead of preprocessing manually?** Guarantees identical transformations at training and prediction time, preventing train/serve skew.
- **What does R² = 0.81 mean?** The model explains ~81% of the variation in final grades; the rest is due to factors not in the data.
- **How do you handle categorical text like "yes"/"no"?** OneHotEncoder converts them into 0/1 columns; `handle_unknown="ignore"` prevents crashes on unseen categories.
- **Why SQLite?** Zero-config, file-based, and sufficient for logging predictions; easy to swap for PostgreSQL later.
